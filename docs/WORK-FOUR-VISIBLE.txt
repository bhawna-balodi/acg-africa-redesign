What We Do — four-point native scroll viewport, 22 October 2026

Desktop image and existing ordered list share a measured height ending at the
bottom of the complete fourth source point. Points5–6 remain in the same DOM
and are reached through native vertical scrolling, with a brand-colour scrollbar.
No carousel, added navigation buttons, wrappers, sticky positioning, scroll
hijacking, snapping, autoplay, image zoom or parallax introduced.

src/scripts/work-viewport.js measures the actual first-four-row boundary,
including current line wrapping and scrollbar gutter. It rounds the resulting
height upward to an even pixel value, and recalculates after fonts load and
when row widths or viewport size change. The image remains object-fit:cover.
Zero-minimum grid/cell widths prevent intrinsic content overflow.

The list receives tabindex0 and aria-labelledby referencing the existing
section heading on desktop. Native keyboard scrolling works; no custom key
handlers or extra focus stops are added. Existing motion/progress scheduling
now also listens passively to list scrolling. Fully reaching the list end
correctly selects the final stage in the existing progress indicator.

At <=1000px the clipping, set height and focus attributes are removed; all six
points appear in normal document flow below the image. Without JavaScript the
same original source list remains wholly visible, with no clipping applied.
Reduced-motion/transparency behavior remains supported.

No DOM element, source text, source list order, branding or imagery changed.
The small sizing initializer is concatenated into the existing motion.js output,
so no stylesheet/script elements or network requests were added.
